# 技术规范

- Java 21
- Spring Boot 3.x
- Spring AI
- PostgreSQL + pgvector
- Redis
- Spring Security
- Flyway
- OpenTelemetry
- Micrometer
- Prometheus
- Grafana

规范：RESTful、统一 Result<T>、SLF4J、JWT、高风险 Tool 二次确认。

## 分层规范

### Controller

- 只处理 HTTP 请求、校验、DTO 转换和 `Result<T>` 响应。
- 不写业务排序、状态流转和 AI 编排。
- 请求 DTO 放在 `controller/dto`。

### Service

- 负责业务用例、事务边界和确定性规则。
- 返回 service DTO，不直接返回 JPA Entity。
- 命令对象放在 `service/dto`。

### Domain

- JPA Entity 和领域枚举放在 `domain`。
- 实体可包含基础生命周期方法，例如 `complete()`、`confirm()`、`reject()`。

### Repository

- 使用 Spring Data JPA。
- 优先使用派生查询。
- 时间范围过滤尽量交给数据库完成。

## REST 规范

统一响应：

```json
{
  "success": true,
  "code": "OK",
  "message": "success",
  "data": {}
}
```

错误响应：

```json
{
  "success": false,
  "code": "BAD_REQUEST",
  "message": "错误原因",
  "data": null
}
```

## AI 工具规范

AI Tool 只做薄封装：

- 参数解析
- 调用 Service
- 记录执行日志
- 返回 `ToolResult`

高风险操作必须二次确认：

- 批量创建待办
- 批量更新待办
- 删除待办
- 确认 AI 计划草案

当前实现允许 AI 创建计划草案，但不允许 AI 直接确认草案。

## 今日计划排序规范

`PlanningService` 使用确定性规则：

1. 只处理 `PENDING` 待办。
2. 逾期任务优先。
3. 高优先级优先。
4. `plannedStartAt` 更早优先。
5. `dueAt` 更早优先。
6. 等待时间更久获得小幅加权。
7. 今日重点最多 3 项。

## 提醒规范

第一版提醒是站内提醒。

扫描规则：

- 默认每 60 秒运行一次。
- 查询 `PENDING` 且 `reminderAt <= now` 的待办。
- 若 `todo_id + reminder_at + channel` 已投递，则跳过。
- 否则写入 `reminder_deliveries`。

配置项：

```yaml
lifepilot:
  reminders:
    scan-delay-ms: 60000
```

## 每日复盘规范

草稿输入：

- `completedAt` 在当天范围内的完成任务。
- `status = PENDING` 且 `plannedStartAt` 在当天范围内的未完成计划任务。
- `createdAt` 在当天范围内的新增任务。

生成策略：

1. 先生成确定性草稿。
2. 尝试 `ReviewDraftClient`。
3. AI 失败时回退确定性草稿。
4. 用户保存后状态为 `SAVED`。

## 数据库迁移规范

- 所有 schema 变化必须新增 Flyway 迁移。
- 命名：`V{number}__description.sql`
- 不修改已发布迁移。
- 新表必须显式声明主键。
- 防重复投递类业务必须增加唯一索引。

当前迁移：

- `V1__init_core_tables.sql`
- `V2__extend_todo_execution_fields.sql`
- `V3__create_user_accounts.sql`
- `V4__create_plan_previews.sql`
- `V5__create_reminder_deliveries.sql`
- `V6__create_daily_reviews.sql`

## 测试规范

- Service 使用 JUnit 5 + Mockito。
- Controller 使用 `@WebMvcTest` + MockMvc。
- 时间相关逻辑使用固定 `Clock`。
- 排序、提醒、复盘必须有确定性测试。
- 完整验证运行：

```powershell
.\gradlew.bat test
```

```powershell
cd frontend
npm run build
```

## 前端规范

- 页面放在 `frontend/src/views`。
- API 客户端放在 `frontend/src/api`。
- 工作台页面直接提供可用流程，不做营销页。
- 表单字段必须与后端 DTO 对齐。
- 日期输入在提交前转换为 API 所需格式。

## 安全与隐私

- 不提交 API Key、JWT Secret、生产凭据。
- 执行日志和 AI 工具输入可能包含个人任务内容，避免记录不必要敏感信息。
- 认证开启后，后续需要继续补齐 Todo、Note、Conversation 等核心数据的用户隔离。
