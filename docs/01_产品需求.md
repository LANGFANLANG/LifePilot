# 产品需求（PRD）

## 项目名称
LifePilot Personal Agent

## 项目目标
打造基于 Spring AI 的个人 AI 助手，支持聊天、待办、笔记、知识库、日程、MCP 与长期记忆。

## MVP
- AI 对话
- Todo
- Notes
- Chat Memory
- Tool Calling
- 执行日志

## 后续
- Calendar
- RAG
- MCP
- Daily Review
- 主动提醒
- 邮件摘要

## 非功能
- OpenTelemetry
- Docker
- PostgreSQL
- Redis

## 当前产品闭环

LifePilot 的当前版本围绕“个人执行”形成六步闭环：

```text
捕获目标 -> 拆解计划 -> 确认待办 -> 今日排序 -> 到点提醒 -> 每日复盘
```

### 目标捕获

用户可以通过 AI 对话输入目标、想法或任务请求。系统保存会话和消息，用于后续上下文延续。

### 计划拆解

当目标需要多个步骤时，AI 应先生成计划草案，而不是直接批量创建待办。计划草案包含：

- 目标描述
- 草案任务列表
- 每个任务的标题、描述、优先级、分类、预计耗时、计划开始时间、提醒时间

### 用户确认

用户在 Chat 页面看到计划草案卡片，可以确认或拒绝。

- 确认：草案任务批量转换为真实待办。
- 拒绝：草案保留为拒绝状态，不污染待办列表。

### 今日排序

Today Dashboard 负责回答“今天先做什么”。排序规则由后端确定性服务完成：

1. 逾期任务优先。
2. 高优先级优先。
3. 计划开始时间更早优先。
4. 截止时间更早优先。
5. 等待时间更久获得小幅加权。

### 提醒

第一版提醒是站内提醒。用户设置 `reminderAt` 后，系统到点写入提醒记录，Today 页面展示最近提醒。

### 每日复盘

用户可以按日期生成复盘草稿。草稿由当天完成任务、未完成计划任务、新增任务组成，用户可以编辑并保存。

## 核心用户故事

### AI 帮我规划目标

用户输入：“帮我规划这个月底上线个人博客。”

系统应：

1. 判断信息是否足够。
2. 信息不足时追问截止日期、可用时间、范围。
3. 信息足够时创建计划草案。
4. 等待用户确认。
5. 用户确认后创建待办。

### 我每天打开首页

用户打开 `/`。

系统应展示：

- 今日重点
- 时间线
- Inbox
- 待处理数量
- 逾期数量
- 预计投入时间
- 最近提醒

### 我晚上做复盘

用户进入 `/review`，点击生成草稿。

系统应：

1. 读取当天完成任务。
2. 读取当天未完成计划任务。
3. 读取当天新增任务。
4. 生成可编辑草稿。
5. 保存用户编辑后的复盘。

## 非目标

当前阶段暂不做：

- 团队协作
- 复杂权限后台
- 付费订阅
- 外部日历双向同步
- 微信、飞书、邮件等外部提醒
- 完整 RAG 知识库

## 后续方向

- 周复盘：聚合每日复盘，输出趋势、阻碍和下周重点。
- 日历视图：围绕 `plannedStartAt` 和 `reminderAt` 展示时间块。
- 外部提醒：浏览器通知、飞书、邮件、Telegram。
- 长期记忆：从笔记、复盘、历史待办中沉淀个人偏好。
- 主动建议：根据逾期、拖延次数、估时偏差给出调整建议。
