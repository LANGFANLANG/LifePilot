# 系统架构

```
Web/App
  │
Spring Boot
  │
Spring AI ChatClient
  │
Agent Service
 ├ Intent
 ├ Memory
 ├ Tool Calling
 ├ RAG
 └ MCP Client
  │
PostgreSQL + pgvector
Redis
OpenTelemetry
```

模块：api、agent、tool、memory、rag、repository、scheduler、observability。

## 当前模块职责

### controller

负责 REST API、请求 DTO、响应包装，不承载业务规则。

主要控制器：

- `ChatController`
- `TodoController`
- `NoteController`
- `PlanPreviewController`
- `PlanningController`
- `ReminderController`
- `DailyReviewController`
- `AuthController`

### service

负责业务用例和确定性规则。

- `TodoService`：待办 CRUD 和完成。
- `PlanPreviewService`：AI 计划草案创建、确认、拒绝。
- `PlanningService`：今日计划排序。
- `ReminderService`：到期提醒扫描和投递记录。
- `DailyReviewService`：每日复盘草稿、读取、保存。
- `ExecutionLogService`：Agent 和工具执行日志。
- `ChatMemoryService`：会话和消息记忆。

### agent

负责 AI 对话适配和结构化动作。

- `AgentService`：保存消息、调用 AI、记录回复和执行日志。
- `SpringAiClient`：Spring AI ChatClient 适配和系统提示词。
- `PlanPreviewActionContext`：记录本轮工具调用产生的计划草案 action。
- `ReviewDraftClient`：AI 复盘草稿接口。
- `NoopReviewDraftClient`：默认降级实现。

### tool

Spring AI 工具层。

- `TodoTool`
- `NoteTool`
- `DateTimeTool`
- `PlanPreviewTool`

计划确认不暴露为 AI 工具，必须由用户通过前端或明确 API 确认。

## 核心数据流

### AI 计划草案

```text
用户输入目标
  -> AgentService 保存 USER 消息
  -> SpringAiClient 调用模型
  -> 模型调用 PlanPreviewTool
  -> PlanPreviewService 保存草案
  -> PlanPreviewActionContext 记录 PLAN_PREVIEW
  -> AgentResponse 返回 content + actions
  -> ChatView 展示草案卡片
  -> 用户确认
  -> PlanPreviewService 批量创建 todos
```

### 今日计划

```text
TodayView
  -> GET /api/planning/today
  -> PlanningService 查询 PENDING todos
  -> 按逾期、优先级、计划开始、截止时间排序
  -> 返回 focus / timeline / inbox / counters
```

### 站内提醒

```text
SchedulerConfig 每分钟触发
  -> ReminderService.deliverDueReminders(now)
  -> 查询 PENDING 且 reminderAt <= now 的 todos
  -> 检查是否已投递
  -> 写入 reminder_deliveries
  -> TodayView 读取最近提醒
```

### 每日复盘

```text
ReviewView 点击生成草稿
  -> DailyReviewController
  -> DailyReviewService 查询当天任务
  -> 生成确定性草稿
  -> 尝试 ReviewDraftClient
  -> AI 失败则回退
  -> 保存 daily_reviews
```

## 架构原则

- AI 负责建议，确定性服务负责落库和排序。
- 高风险 AI 操作必须用户确认。
- AI 不可用时，待办、提醒、复盘仍可用。
- DTO 与 JPA Entity 分离。
- Controller 薄，Service 厚。
- 所有 schema 变化通过 Flyway 迁移。
